# ระบบเลขครุภัณฑ์แบบกำหนดรูปแบบได้

## เป้าหมาย

ให้ CAMMS Portal รองรับเลขครุภัณฑ์ของหลายหน่วยงานโดยไม่สมมติว่ามีรูปแบบราชการกลางเพียงแบบเดียว และคงการใช้งานข้อมูลเดิมไว้ได้ ระบบต้องรองรับการได้เลขมาสามทางในรายการครุภัณฑ์ (`item_type = asset`):

1. ผู้ใช้กรอกเลขเต็มเอง
2. ผู้ใช้สร้างเลขจากแม่แบบของหน่วยงาน
3. ระบบออกเลขลำดับถัดไปจากแม่แบบอย่างปลอดภัย

การนำเข้า CSV เป็นช่องทางรับข้อมูลที่สี่ โดยยอมรับเลขเดิมทั้งแบบที่ตรงและไม่ตรงกับแม่แบบ พร้อมบันทึกที่มาของเลขไว้ตรวจสอบได้

ตัวอย่างแม่แบบที่ต้องสร้างได้คือ `สขส7.7110-006-0001-11/58` โดยประกอบด้วยข้อความคงที่และส่วนข้อมูล เช่น หน่วยงาน กลุ่ม หมวด ลำดับ และปี

## ขอบเขตและคำศัพท์

- เลขครุภัณฑ์เก็บในคอลัมน์เดิม `items.asset_no`; หน้าค้นหา รายงาน ป้ายทรัพย์สิน และการส่งออกจึงทำงานต่อได้โดยไม่ต้องย้ายข้อมูล
- แม่แบบเป็นของการตั้งค่าระบบ ไม่ผูกกับหมวดหรือสถานที่ในระยะแรก
- `manual`, `template`, `automatic`, และ `import` คือที่มาของเลข ไม่ใช่สถานะของรายการ
- วัสดุ (`item_type = material`) ไม่มีขั้นตอนออกเลขครุภัณฑ์ และคงส่งค่า `asset_no` ว่าง
- จะไม่มีแม่แบบเริ่มต้นที่แอบกำหนดรหัสหน่วยงานให้ผู้ใช้ ต้องสร้าง/เปิดใช้แม่แบบก่อนจึงออกเลขอัตโนมัติได้

## ทางเลือกที่พิจารณา

### A. กำหนดรูปแบบตายตัวในโค้ด

สร้างได้เร็ว แต่ไม่รองรับความต่างของหน่วยงานและแก้ทุกครั้งต้องแก้โค้ด/ย้ายข้อมูล จึงไม่เลือก

### B. แม่แบบบนหน้าจอ แต่ให้หน้าเว็บคำนวณเลขรัน

ยืดหยุ่นในหน้าจอ แต่เกิดเลขซ้ำได้เมื่อเจ้าหน้าที่หลายคนบันทึกพร้อมกัน จึงไม่เลือก

### C. แม่แบบกำหนดได้ + ผู้ออกเลขในฐานข้อมูล (เลือกใช้)

ให้ผู้ดูแลตั้งค่าโครงสร้างและค่าตั้งต้นได้ ขณะที่ฐานข้อมูลจองเลขลำดับถัดไปในธุรกรรมเดียวและบังคับเลขไม่ซ้ำ เหมาะกับข้อมูลราชการและข้อมูลนำเข้าเดิม

## แบบข้อมูล

เพิ่มตาราง `asset_number_templates` ซึ่งเข้าถึงได้เฉพาะผู้ดูแลสำหรับการเขียน และผู้ใช้ที่เข้าสู่ระบบอ่านได้เพื่อแสดงตัวเลือก:

| ฟิลด์ | ความหมาย |
| --- | --- |
| `id` | UUID ของแม่แบบ |
| `name` | ชื่อที่ผู้ดูแลเห็น เช่น “สขส. ปีงบประมาณ 2558” |
| `pattern` | นิพจน์แม่แบบที่เก็บตัวคั่นและลำดับส่วน เช่น `{org}.{group}-{class}-{running:4}-{subclass}/{year:2}` |
| `fields` | นิยามค่าของ token ที่กรอก/ล็อกได้ รวมค่าเริ่มต้นและ validation |
| `sequence_scope` | ชุดข้อมูลที่แยกเลขรัน เช่น แม่แบบ + ค่า token ที่เลือกไว้ + ปี |
| `is_active` | เปิดใช้หรือปิดใช้; ปิดแล้วไม่ออกเลขใหม่ แต่ประวัติเดิมยังอ่านได้ |
| `created_at`, `updated_at`, `created_by`, `updated_by` | ร่องรอยการตั้งค่า |

เพิ่มเมทาดาทาลง `items`:

| ฟิลด์ | ความหมาย |
| --- | --- |
| `asset_number_source` | `manual`, `template`, `automatic`, `import`, หรือ `legacy` สำหรับข้อมูลเดิม |
| `asset_number_template_id` | แม่แบบที่ใช้เมื่อมี |
| `asset_number_payload` | ค่าของ token ตอนออกเลข เพื่ออธิบายและสร้างเลขซ้ำได้แม้แม่แบบภายหลังถูกแก้ |

เพิ่มตารางตัวนับภายใน `asset_number_sequences` ที่มีคีย์ไม่ซ้ำต่อ `template_id` และ `sequence_scope` พร้อมค่า `last_issued` ห้ามให้ client แก้โดยตรง

การย้ายข้อมูลกำหนดข้อมูล `items` ที่มีเลขเดิมเป็น `legacy`; รายการที่ไม่มีเลขคงค่า `NULL` ในเมทาดาทา

ข้อกำหนดความไม่ซ้ำของ `items.asset_no` ต้องครอบคลุมทุกรายการที่ยังมีอยู่จริง เพราะการลบแบบถาวรทำให้เลขที่ถูกลบสามารถนำกลับมาใช้ได้ตามสภาพข้อมูลฐานข้อมูล ไม่สร้าง index ที่อ้าง `deleted_at` อีก Migration นี้ต้องรันหลัง migration การลบถาวร (`00035`) และต้องย้ายชื่อ/การตรวจ error เดิมที่อ้าง `unique_asset_no_not_deleted` ให้รองรับชื่อ constraint ใหม่

## การตั้งค่าแม่แบบ

เพิ่มแท็บ “เลขครุภัณฑ์” ในการตั้งค่าระบบสำหรับ admin เท่านั้น

ผู้ดูแลสามารถสร้าง แก้ไข เปิด/ปิด และทดสอบแม่แบบได้ หน้าทดสอบแสดงผลตัวอย่างก่อนบันทึกและบอก token ที่ยังไม่ครบ ตัวแก้ไขไม่ใช่การพิมพ์ regex: เลือกส่วนข้อมูลและตัวคั่นเป็นลำดับ เพื่อให้กรอกง่ายและลดรูปแบบที่สร้างไม่ได้

token รุ่นแรก:

- `literal`: ข้อความคงที่ เช่น `สขส7`, `.`, `-`, `/`
- `text`: ข้อความ/รหัสที่ผู้ใช้งานเลือกหรือกรอก เช่น `7110`, `006`, `11`
- `running`: เลขรัน บังคับความกว้างและเติมศูนย์ด้านหน้า เช่น `0001`
- `year`: ปี คำนวณจากวันที่ได้มา/ปีงบประมาณตามการตั้งค่า และเลือกได้ 2 หรือ 4 หลัก

แม่แบบต้องมี `running` ได้หนึ่งตัวเท่านั้น ต้องมีอย่างน้อยหนึ่งส่วน และต้องสร้างเลขได้ไม่เกิน 150 ตัวอักษร แก้ไขแม่แบบจะมีผลกับการออกเลขครั้งถัดไปเท่านั้น ไม่เปลี่ยนเลขหรือ payload ของรายการเก่า

## หน้าลงทะเบียนครุภัณฑ์

ในฟอร์มรายการชนิดครุภัณฑ์ ส่วน “เลขครุภัณฑ์” เป็นตัวเลือกวิธีได้เลข โดยค่าเริ่มต้นคือ “เลือกวิธี” เพื่อไม่ออกเลขโดยไม่ตั้งใจ:

| วิธี | พฤติกรรม |
| --- | --- |
| กรอกเอง | แสดงช่อง `asset_no`; ตรวจความยาวและเลขซ้ำตอนบันทึก |
| สร้างจากแม่แบบ | เลือกแม่แบบ กรอก token ที่เปิดให้กรอก **รวมเลข running ด้วยตนเอง** แล้วเห็นตัวอย่าง; บันทึกค่าตามตัวอย่างโดยไม่แตะตัวนับอัตโนมัติ |
| ออกเลขอัตโนมัติ | เลือกแม่แบบ/ค่า token แล้วแสดง “เลขถัดไปโดยประมาณ”; ตอนกดบันทึกจึงจองเลขจริงและแสดงเลขที่ออกสำเร็จ |

“เลขถัดไปโดยประมาณ” ไม่ใช่การรับประกัน เพราะอาจมีผู้อื่นออกเลขก่อน ผู้ใช้ต้องเห็นผลลัพธ์จริงหลังบันทึกเสมอ

ถ้าไม่มีแม่แบบ active ให้แสดงเฉพาะการกรอกเอง และมีข้อความสำหรับ admin ว่าสามารถตั้งค่าแม่แบบได้ที่ตั้งค่าระบบ ผู้ใช้ทั่วไปไม่เห็นปุ่มไปหน้าตั้งค่า

รายการเดิมแก้ไขเลขได้เฉพาะเจ้าหน้าที่ที่มีสิทธิ์แก้ไข โดยเปิดเป็น “เปลี่ยนวิธี/เลข” ชัดเจนเพื่อป้องกันการเปลี่ยนเลขโดยไม่ตั้งใจ การออกเลขอัตโนมัติใหม่จากหน้าแก้ไขต้องใช้ตัวนับเดียวกันและบันทึก audit log

## การออกเลขอัตโนมัติและความถูกต้อง

เพิ่ม Postgres RPC สำหรับการบันทึกรายการครุภัณฑ์พร้อมจองเลข ไม่ให้ browser ส่งเลขรันสุดท้ายมาเป็นข้อเท็จจริง กระบวนการอยู่ใน transaction เดียว:

1. ตรวจสิทธิ์ editor และตรวจแม่แบบ active
2. ตรวจ token ตามนิยามแม่แบบ และสร้าง `sequence_scope` แบบ canonical
3. lock หรือ upsert แถวตัวนับตามแม่แบบและ scope แล้วเพิ่ม `last_issued`
4. render เลขจาก payload และค่า running ที่จอง
5. insert/update item พร้อม `asset_no`, source, template และ payload
6. หากเลขซ้ำหรือ validation ไม่ผ่าน ให้ rollback ทั้งการออกเลขและการบันทึกรายการ
7. เขียน audit log ที่ระบุวิธี ที่มา แม่แบบ และเลขที่ออก

เลขที่ออกแล้วไม่คืนลำดับแม้ภายหลังผู้ใช้ลบรายการ เพื่อป้องกันการใช้เลขราชการซ้ำโดยอุบัติเหตุ หาก transaction ล้มเหลวก่อน commit เลขนั้นไม่ถือว่าออก

การตรวจเลขซ้ำต้องทำทั้ง client เพื่อ feedback และ server/database เพื่อความถูกต้องจริง ข้อความผิดพลาดต้องเป็นภาษาไทยและไม่เปิดเผยข้อมูลเกินสิทธิ์

## การนำเข้า CSV

คงคอลัมน์ `asset_no` เดิมในแม่แบบ CSV เพื่อความเข้ากันได้ และเพิ่มคอลัมน์เลือกได้:

- `asset_number_template` — ชื่อ/รหัสแม่แบบที่ต้องการตรวจ
- token ตามแม่แบบ เช่น `asset_org`, `asset_group`, `asset_class`, `asset_subclass`, `asset_year`
- `asset_number_source` — รับค่า `manual` หรือ `import`; ไม่รับ `automatic` เพื่อไม่ให้ import จองเลขโดยไม่ตั้งใจ

กติกา import:

1. ถ้ามี `asset_no` อย่างเดียว: นำเข้าได้เป็น `import` แม้ไม่ตรงแม่แบบ พร้อมคำเตือนในผลตรวจว่าเป็นเลข legacy/external
2. ถ้ามีแม่แบบและ token ครบ: render ผลแล้วต้องเท่ากับ `asset_no`; ถ้าไม่เท่ากัน รายการบรรทัดนั้นผิดพลาด
3. ถ้ามีแม่แบบแต่ไม่มี `asset_no`: import preview สร้างตัวอย่างได้ แต่ไม่ออกเลขอัตโนมัติในรุ่นนี้; ผู้ใช้ต้องส่งออก/ตรวจแล้วใช้หน้าลงทะเบียนหรือ API เฉพาะในอนาคต
4. เลขซ้ำกับรายการปัจจุบัน หรือซ้ำกันเองในไฟล์ เป็น line error โดยไม่เขียนบรรทัดนั้น ตามพฤติกรรม import ปัจจุบัน

ผล import ต้องแสดงจำนวนสำเร็จ/ผิดพลาด แถวและเหตุผล พร้อมบันทึก audit ของการนำเข้า โดยไม่ทำให้ template ที่ปิดใช้งานกลับมา active

## สิทธิ์ ความปลอดภัย และ Audit

- admin จัดการแม่แบบและดูการตั้งค่าตัวนับได้
- staff ใช้แม่แบบ active, กรอกเอง, ออกเลขอัตโนมัติ และ import ตามสิทธิ์นำเข้าปัจจุบัน
- viewer อ่านเลขและที่มาได้ แต่ไม่ออก/แก้/import
- RLS ป้องกันการเขียนตารางแม่แบบและตัวนับโดยตรงจาก client; RPC ตรวจบทบาทจาก session ไม่ไว้ใจ payload
- audit log เก็บการสร้าง/แก้/เปิดปิดแม่แบบ การออกเลข การเปลี่ยนเลข และการนำเข้า พร้อมเลขเก่า/ใหม่และ template ที่เกี่ยวข้อง

## ขอบเขตที่ไม่ทำในรุ่นแรก

- ไม่จัดทำหรือรับรองรูปแบบเลขกลางของราชการ
- ไม่ดึงข้อมูลจากระบบทะเบียนภายนอก
- ไม่สร้าง QR/barcode ใหม่จากเลขนี้
- ไม่อนุญาต import ให้จองเลขอัตโนมัติทีละมาก ๆ
- ไม่แก้ไขเลขเดิมจำนวนมากด้วย bulk action

## ลำดับการส่งมอบ

1. โครงสร้างฐานข้อมูล, RLS, unique constraint, RPC, audit และ migration สำหรับเลขเดิม
2. หน้าตั้งค่าแม่แบบพร้อม preview และ validation สำหรับ admin
3. ฟอร์มครุภัณฑ์: กรอกเอง, สร้างจากแม่แบบ และออกเลขอัตโนมัติ
4. CSV import validation และเมทาดาทา/ผลลัพธ์
5. ชุดทดสอบ schema, renderer, scope, authorization, RPC/error mapping และ regression ของ import

## เกณฑ์ยอมรับ

- สร้างแม่แบบตัวอย่าง `สขส7.7110-006-0001-11/58` ได้โดยไม่แก้โค้ด
- ผู้ใช้สองคนออกเลขพร้อมกันจาก scope เดียวกันแล้วได้เลขไม่ซ้ำและลำดับต่อเนื่องตาม transaction ที่สำเร็จ
- ผู้ใช้กรอกเลขเต็มเองได้ แต่บันทึกเลขซ้ำไม่ได้
- ข้อมูล CSV ที่มี `asset_no` แบบเก่านำเข้าได้และระบุ source เป็น `import`
- CSV ที่อ้างแม่แบบแต่เลขไม่ตรง token ถูกปฏิเสธเป็น line error โดยไม่ทำให้รายการอื่นในไฟล์เสีย
- รายการเก่ายังแสดง ค้นหา รายงาน และส่งออก `asset_no` ได้เหมือนเดิม
