# ข้อกำหนดการเบิกจ่ายวัสดุ

วันที่: 16 พฤศจิกายน 2569

สถานะ: ข้อเสนอเดิม ส่วนที่กล่าวถึงการจองถูกแทนที่ด้วยข้อกำหนดล่าสุดด้านล่าง

## ข้อกำหนดล่าสุดที่ผู้ใช้ยืนยัน

ผู้ใช้ยกเลิกการจองวัสดุ และให้ตัดสต็อกจริงทันทีเมื่อส่งคำขอเบิก โดยเอกสารยังรออนุมัติอยู่ เมื่ออนุมัติห้ามตัดซ้ำ หากยกเลิกหรือปฏิเสธให้คืนยอดที่เคยตัดเพียงครั้งเดียว ร่างไม่ตัดสต็อก คำขอเก่าที่ไม่มีประวัติตัดยอดยังใช้เส้นทางตัดตอนอนุมัติ ไม่มีการหักย้อนหลังอัตโนมัติ

พัฒนาตามข้อกำหนดล่าสุดแล้ว ดู [รายละเอียดการเปลี่ยนแปลงและผลทดสอบ](../plans/2026-11-16-immediate-material-stock.md) เนื้อหาการจองด้านล่างเก็บไว้เป็นประวัติข้อเสนอเดิม ไม่ใช่กติกาปัจจุบัน

## วัตถุประสงค์

ให้วัสดุในทะเบียนที่มีจำนวนพร้อมจ่ายตั้งแต่ 1 หน่วยขึ้นไปสามารถเลือกขอเบิกได้ โดยตรวจสถานะ จำนวน และสิทธิ์ให้ครบก่อนบันทึกจ่ายจริง ป้องกันสต็อกติดลบและรองรับผู้ขอเบิกหลายคนพร้อมกัน

คำว่า “หน่วย” อ้างอิงหน่วยนับของวัสดุ เช่น ชิ้น รีม กล่อง ขวด หรือแกลลอน ระบบปัจจุบันรับจำนวนเต็ม จึงยังไม่รองรับการเบิกเศษหน่วยโดยอัตโนมัติ

เอกสารนี้เป็นข้อกำหนดการทำงานของ CAMMS ไม่ใช่ข้อรับรองว่าครบระเบียบพัสดุของทุกหน่วยงาน

## ขอบเขต

- ใช้กับเอกสารเบิกวัสดุ `material_issue` และรายการในทะเบียนวัสดุ
- ครอบคลุมรายการให้เลือก การขอเบิก การแก้ไข การจอง การอนุมัติ การตัดสต็อก และการยกเลิก
- คงบทบาทและสิทธิ์เดิมของผู้ใช้และผู้ดูแลระบบ
- ไม่เปลี่ยนเงื่อนไขการยืมหรือส่งมอบครุภัณฑ์
- ไม่เปลี่ยนยอดเดิมจาก Excel หรือสูตรค่าเสื่อมราคา

## เงื่อนไขการเลือกขอเบิก

วัสดุจะเลือกขอเบิกได้เมื่อผ่านทุกเงื่อนไข:

1. เป็นรายการประเภทวัสดุ และยังไม่ถูกลบ
2. สถานะพร้อมใช้งาน เช่น `active` หรือ `spare` ตามการรองรับสถานะเดิม
3. จำนวนพร้อมจ่ายไม่น้อยกว่า 1 หน่วย
4. ผู้ขอมีสิทธิ์สร้างคำขอเบิกตามระบบเดิม

ไม่บังคับ `is_central` สำหรับวัสดุ โดยตั้งสมมติฐานว่าทะเบียนวัสดุนี้เป็นวัสดุในคลังที่มีไว้เบิกจ่าย หากภายหลังมีวัสดุเฉพาะหน่วยงานที่ห้ามเบิกข้ามหน่วยงาน ต้องกำหนดขอบเขตคลังหรือสิทธิ์เพิ่มเติมอย่างชัดเจน

ห้ามใช้ข้อความในหมายเหตุ เช่น “ส่วนกลาง” เป็นตัวตัดสินสิทธิ์เบิกวัสดุ

วัสดุหมดหรือไม่พร้อมใช้งานอาจแสดงเพื่อให้ค้นหาได้ แต่ต้องปิดการเลือกและแสดงเหตุผล เช่น “คงเหลือ 0 หน่วย” หรือ “ชำรุด”

## นิยามจำนวน

| ชื่อ | ความหมาย |
|---|---|
| จำนวนคงเหลือปัจจุบัน | จำนวนที่ระบบบันทึกหลังรายการรับ–จ่ายที่เกิดขึ้นจริง |
| จำนวนจอง | ผลรวมจำนวนจากคำขอที่ส่งแล้วและยังรออนุมัติ |
| จำนวนพร้อมจ่าย | จำนวนคงเหลือปัจจุบัน − จำนวนจอง |
| จำนวนขอเบิก | จำนวนที่ผู้ขอระบุในเอกสาร |
| จำนวนจ่ายจริง | จำนวนที่ตัดสต็อกเมื่ออนุมัติสำเร็จ |

แนวทางที่เสนอคือจองตามจำนวนเมื่อส่งคำขอเข้าสถานะรออนุมัติ ไม่จองทั้งรายการ และไม่จองจากเอกสารร่าง

ตัวอย่าง: มี 10 รีม คำขอ A จอง 3 รีม อีกคนยังขอได้ 7 รีม ไม่ปิดกั้นกระดาษทั้งรายการ

การคำนวณจำนวนจองต้องนับเฉพาะคำขอที่ยังมีผล ห้ามนับคำขอที่อนุมัติและตัดสต็อกแล้วซ้ำอีกครั้ง ห้ามนับเอกสารยกเลิกหรือปฏิเสธ

## กติกาจำนวนขอเบิก

- เป็นจำนวนเต็มตั้งแต่ 1 หน่วย และไม่เกินขอบเขตจำนวนที่ฐานข้อมูลรองรับ
- ไม่เกินจำนวนพร้อมจ่าย
- ห้ามรายการวัสดุเดียวกันซ้ำหลายบรรทัดในเอกสารเดียว เพื่อป้องกันการหลบเงื่อนไขตรวจจำนวน
- แสดงหน่วยนับควบคู่จำนวนทุกครั้ง
- การแก้ไขคำขอเดิมต้องไม่นับยอดจองของตัวเองซ้ำ เช่น มี 10 จองของตัวเอง 3 และคนอื่นจอง 2 จะแก้คำขอของตัวเองได้สูงสุด 8
- เปลี่ยนรายการหรือจำนวนแล้วต้องตรวจใหม่ที่ฝั่งเซิร์ฟเวอร์

เกณฑ์จำนวนต่ำสุดเป็นตัวแจ้งเตือนสำหรับจัดซื้อ ไม่ใช่ข้อห้ามเบิกโดยอัตโนมัติในข้อเสนอนี้ เช่น เหลือ 5 ขั้นต่ำ 10 ยังขอได้สูงสุด 5 หากไม่มีการจองอื่น

## ลำดับการทำงาน

| ขั้นตอน | สิ่งที่ระบบต้องทำ | ผลต่อสต็อก |
|---|---|---|
| เลือกวัสดุ | แสดงจำนวนคงเหลือ จำนวนจอง และจำนวนพร้อมจ่าย | ไม่มี |
| บันทึกร่าง | ตรวจรูปแบบและข้อมูลเอกสาร | ไม่จองและไม่ตัด |
| ส่งคำขอ | ตรวจสิทธิ์ สถานะ และจำนวนพร้อมจ่ายอีกครั้ง | จองจำนวนที่ขอ |
| แก้ไขคำขอที่ยังแก้ได้ | ตรวจใหม่และปรับยอดจองภายในธุรกรรมเดียว | เปลี่ยนเฉพาะยอดจอง |
| อนุมัติ/ยืนยันจ่าย | ตรวจข้อมูลล่าสุด ตัดสต็อก และบันทึกหลักฐาน | ลดคงเหลือและปล่อยยอดจองของคำขอนี้ |
| ปฏิเสธ/ยกเลิกก่อนจ่าย | ตรวจสิทธิ์และสถานะเอกสาร | ปล่อยยอดจอง ไม่เพิ่มคงเหลือ |
| ย้อนรายการที่จ่ายแล้ว | ใช้เส้นทางย้อนรายการเดิม พร้อมเหตุผลและการตรวจสิทธิ์ | คืนจำนวนที่เคยจ่ายจริงเพียงครั้งเดียว |

อนุญาตให้เปลี่ยนสถานะหรือแก้ไขเอกสารได้เฉพาะตามสิทธิ์และขั้นตอนเดิม ไม่ขยายสิทธิ์จากการยกเลิกเงื่อนไขส่วนกลาง

## การอนุมัติและความถูกต้องเมื่อทำพร้อมกัน

การตรวจจากหน้าจอเพียงอย่างเดียวไม่เพียงพอ ต้องตรวจที่เซิร์ฟเวอร์และใช้ธุรกรรมฐานข้อมูล:

1. ล็อกเอกสารและรายการวัสดุที่เกี่ยวข้องตามลำดับ ID ที่คงที่
2. อ่านสถานะและยอดล่าสุด รวมยอดจองของคำขออื่น
3. ตรวจว่าเอกสารยังอยู่ในสถานะที่ทำรายการนี้ได้
4. ตรวจยอดพร้อมจ่าย โดยไม่นับยอดจองของเอกสารปัจจุบันซ้ำ
5. ตัดสต็อก บันทึกจำนวนจ่ายจริง ประวัติสต็อก ผู้อนุมัติ และสถานะเอกสารในธุรกรรมเดียว
6. หากรายการใดไม่ผ่าน ให้ rollback ทั้งเอกสาร ไม่ตัดเฉพาะบางรายการ

การสร้างหรือแก้ไขยอดจองต้องใช้กลไกล็อกเดียวกัน เพื่อป้องกันสองคำขออ่านยอดว่างเดียวกันแล้วจองเกินพร้อมกัน

ต้องมีการป้องกันจำนวนติดลบในคำสั่งตัดสต็อก/ข้อจำกัดฐานข้อมูล และตรวจจำนวนแถวที่อัปเดต ห้ามถือว่าการกดปุ่มได้หมายถึงจ่ายสำเร็จ

การกดซ้ำหรือส่งคำขอเดิมซ้ำต้องไม่ตัดสต็อกหรือคืนสต็อกซ้ำ หากทำรายการไปแล้ว ให้คืนผลที่เหมาะสมหรือแจ้งว่าเอกสารเปลี่ยนสถานะแล้ว

ข้อเสนอนี้ให้จ่ายเต็มจำนวนที่ขอหรือปฏิเสธ หากต้องการจ่ายบางส่วน ต้องออกแบบจำนวนจ่ายจริง ยอดค้าง และการปิดคำขอเพิ่มเติมก่อนพัฒนา

## ข้อมูลที่ผู้ใช้ควรเห็น

- ชื่อวัสดุ รหัส หน่วยนับ สถานะ
- จำนวนคงเหลือ จำนวนจอง จำนวนพร้อมจ่าย
- ช่องจำนวนขอเบิก พร้อมค่าสูงสุดตามข้อมูลล่าสุด
- ผู้รับ กลุ่มงาน และวัตถุประสงค์ตามฟอร์มเดิม
- ข้อผิดพลาดระบุชื่อวัสดุและจำนวน เช่น “กระดาษ A4 พร้อมจ่าย 3 รีม แต่ขอเบิก 4 รีม”
- เมื่อข้อมูลเปลี่ยนระหว่างเปิดหน้า ให้แจ้งยอดล่าสุดและให้ผู้ใช้แก้จำนวน

ห้ามปรับลดจำนวนที่ขอเองเงียบ ๆ และห้ามแปลงหน่วย เช่น กล่องเป็นชิ้น โดยไม่มีอัตราแปลงที่กำหนดไว้

## ความสัมพันธ์กับบัญชี Excel

ใช้จำนวนคงเหลือปัจจุบันสำหรับตรวจและตัดสต็อก ไม่ใช้ยอดยกมา จำนวนเงิน หรือจำนวนรับ–จ่ายจากไฟล์ต้นฉบับเป็นยอดพร้อมจ่าย

ยอดยกมา รับ จ่าย และจำนวนเงินตาม Excel เป็นข้อมูลอ้างอิง ณ วันที่ของต้นฉบับ ไม่ควรถูกเขียนทับจากการเบิกจ่ายปัจจุบัน ต้องบันทึกความเคลื่อนไหวใหม่ในประวัติของระบบ

การมีราคาต่อหน่วยว่างไม่ใช่เหตุให้เลือกขอเบิกไม่ได้ตามข้อเสนอนี้ ส่วนวิธีตีมูลค่าการจ่ายและรายงานบัญชีต้องกำหนดแยก และไม่แปลงราคาที่ไม่ทราบเป็นศูนย์โดยอัตโนมัติ

## จุดต่างจากโค้ดปัจจุบันที่ต้องปรับเมื่อเริ่มพัฒนา

| ส่วน | หลักฐานจากโค้ด | พฤติกรรมเป้าหมาย |
|---|---|---|
| รายการให้เลือก | `features/disbursements/postgres-queries.ts` กรอง `is_central` หรือคำว่าส่วนกลางในหมายเหตุ | สำหรับวัสดุ ให้พิจารณาประเภท สถานะ และจำนวนพร้อมจ่าย |
| ตรวจส่วนกลาง | `features/disbursements/postgres-actions.ts` เรียก `assertCentralDisbursementItem` ในเส้นทางสร้าง แก้ไข และอนุมัติ | ยกเว้นวัสดุเฉพาะเส้นทาง `material_issue` และคงกติกาครุภัณฑ์ |
| การจอง | `features/disbursements/reservations.ts` และการตรวจ `reserved` ใช้การกันระดับรายการ | แยกการจองวัสดุตามจำนวนออกจากการจองครุภัณฑ์ |
| สถานะพร้อมเลือก | `features/disbursements/catalog-availability.ts` ตัดสินจาก boolean `reserved` | รองรับยอดจองและจำนวนพร้อมจ่ายสำหรับวัสดุ |
| ตรวจจำนวน | `features/disbursements/schema.ts` ตรวจจำนวนเต็มตั้งแต่ 1 และห้ามรายการซ้ำแล้ว | คงกติกานี้ และตรวจยอดล่าสุดในธุรกรรม |
| ตัด/คืนสต็อก | `features/disbursements/postgres-actions.ts` มีเส้นทางลดจำนวนวัสดุเมื่ออนุมัติและเพิ่มเมื่อย้อนรายการ | ทดสอบร่วมกับยอดจองใหม่และป้องกันการทำซ้ำ |

ต้องตรวจผู้เรียกฟังก์ชันร่วมทั้งหมดก่อนเปลี่ยน ห้ามถอดการตรวจส่วนกลางหรือการจองออกจากฟังก์ชันกลางโดยทำให้ครุภัณฑ์เปลี่ยนพฤติกรรมตามไปด้วย

## เกณฑ์ทดสอบรับงาน

| กรณี | ผลที่ต้องได้ |
|---|---|
| วัสดุ active เหลือ 1 ไม่ใช่ส่วนกลาง | เลือกขอเบิก 1 ได้ |
| วัสดุ spare เหลือ 2 | เลือกได้ตามการรองรับสถานะเดิม |
| เหลือ 0 | เลือกไม่ได้ และเซิร์ฟเวอร์ปฏิเสธคำขอ |
| วัสดุชำรุด/เสื่อมสภาพ/จำหน่าย/ถูกลบ แต่จำนวนมากกว่า 0 | ขอเบิกไม่ได้ |
| เหลือ 3 ขอ 4 | ปฏิเสธและแจ้งจำนวนพร้อมจ่าย |

| บันทึกร่างไว้หลายฉบับ | ไม่ทำให้พร้อมจ่ายลดลง |
| สองคนส่งขอ 4 พร้อมกันจากคงเหลือ 5 | ยอดจองรวมต้องไม่เกิน 5 |
| อนุมัติคำขอที่จอง 3 จากคงเหลือ 10 | คงเหลือ 7 และไม่หักยอดจอง 3 ซ้ำอีก |
| ยกเลิก/ปฏิเสธคำขอจอง 3 | ปล่อยจอง 3 โดยคงเหลือจริงไม่เปลี่ยน |
| หลายรายการในเอกสาร มีหนึ่งรายการจ่ายไม่ได้ | ไม่มีรายการใดถูกตัดสต็อก |
| กดอนุมัติหรือย้อนรายการซ้ำ | สต็อกเปลี่ยนเพียงครั้งเดียว |
| สต็อกหรือสถานะเปลี่ยนหลังเปิดหน้า | ตรวจใหม่และแจ้งผลจากข้อมูลล่าสุด |
| จำนวนต่ำกว่าเกณฑ์ขั้นต่ำ แต่ยังพร้อมจ่าย | เบิกได้ พร้อมแสดงคำเตือนตามความเหมาะสม |
| ราคาว่างแต่มีสต็อก | ขอเบิกได้ และคงความหมายว่าราคาไม่ทราบ |
| ผู้ไม่มีสิทธิ์เรียก API โดยตรง | ปฏิเสธตามสิทธิ์เดิม |
| ครุภัณฑ์ไม่ใช่ส่วนกลาง หรือถูกจองอยู่ | ยังใช้ข้อจำกัดเดิมของครุภัณฑ์ |

## ลำดับงานที่เสนอ

1. กำหนดการคำนวณจำนวนจองและจำนวนพร้อมจ่ายสำหรับวัสดุ พร้อมทดสอบ
2. ปรับรายการให้เลือกและเหตุผลที่เลือกไม่ได้ โดยแยกจากครุภัณฑ์
3. ปรับสร้าง/ส่ง/แก้ไขคำขอให้จองตามจำนวนอย่างปลอดภัย
4. ปรับอนุมัติ ปฏิเสธ ยกเลิก และย้อนรายการให้สอดคล้องกัน
5. ทดสอบฐานข้อมูลด้วยธุรกรรมพร้อมกัน รวมเส้นทางครุภัณฑ์เดิม
6. ทดสอบหน้าจอขอเบิกจนถึงการอนุมัติและการแสดงยอดล่าสุด

การพัฒนาตามเอกสารนี้ควรเริ่มเป็นงานถัดไป การจัดทำเอกสารไม่ได้หมายความว่าเงื่อนไขดังกล่าวถูกนำไปใช้แล้ว
